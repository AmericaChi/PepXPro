PepXPro Tutorial
===============
End-to-end walkthrough of the pipeline and six application workflows.
Audience: computational biologists familiar with protein structure and MD/docking tools.

All commands assume the pepxpro conda environment is active:
  conda activate pepxpro

PART 1 — FULL PIPELINE WALKTHROUGH
=============================================================================

What PepXPro does
----------------
PepXPro extracts all peptide-protein co-crystal structures from PDBbind, fixes
them (missing residues, AMBER14 compatibility), annotates them (sequences, SS,
functional class, affinity), and exposes a flexible sampling pipeline to build
reproducible, diversity-aware benchmark datasets.

Starting point: PDBbind INDEX_general_PL.2020 (requires registration at
pdbbind.org). Place the index file at:
  scrape_pdb_bind/inputs/INDEX_general_PL.2020


--- 1.1  scrape_pdb_bind ---

Move into the scripts directory for all scrape commands:
  cd scrape_pdb_bind/scripts

STEP 1 — Download
  Parses the PDBbind index for n-mer entries with Kd or Ki affinity.
  Downloads all biological assembly CIFs from RCSB. ~750 entries, ~30 min.

  python 01_download.py

  Key outputs:
    pdb_cache/           Raw assembly CIFs
    outputs/peptide_entries.tsv   pdb_id, n_mer, year, dG_kcal, binding_type

STEP 2 — Filter and fix
  Selects the best assembly, identifies peptide/receptor chains, checks AMBER14
  compatibility, fills missing residues with PDBFixer, runs DSSP, and annotates
  receptor functional class from PDB entity descriptions.

  python 02_filter.py

  The filter is incremental: re-running skips already-processed entries and
  cheaply patches any new columns (e.g. receptor_func_class) without repeating
  the heavy PDBFixer/DSSP steps.

  Key outputs:
    fixed_cif/                    Fixed, AMBER14-compatible CIFs
    outputs/filtered_systems.tsv  Per-entry results (accepted/rejected + metadata)

STEP 3 — Summary
  Joins filter results with affinity data, computes SS fractions, sorts by ΔG.

  python 03_summary.py

  Key output:
    outputs/summary.tsv    ~739 entries (varies by PDBbind version)

STEP 4 — Distributions (optional)
  Generates box plots for all numeric columns in summary.tsv.

  python 04_distributions.py

  Output: outputs/plots/summary_distributions.png


--- 1.2  Adding an external dataset (optional) ---

PepXPro can integrate any external affinity dataset (xlsx, tsv, csv) alongside
PDBbind. The example below uses PEPBI (Dryad, doi:10.5061/dryad.wstqjq2wk).

  cd scrape_pdb_bind/scripts

  python 05_external.py \
    --input inputs/external/PEPBI.xlsx \
    --name pepbi_v1

  What happens:
    1. Loads the dataset and auto-detects column mapping (saves pepbi_v1_colmap.json).
    2. Deduplicates against PDBbind — entries already in the database are skipped.
    3. Downloads missing CIFs and fills year + resolution from CIF and RCSB API.
    4. Runs steps 2 and 3 on the new entries.
    5. Merges with summary.tsv → outputs/summary_merged.tsv.

  To add a second dataset later:
    python 05_external.py --input inputs/external/my_dataset.tsv --name custom_v1

  To rebuild the merged file after adding multiple sources:
    python 05_external.py --merge-only

  The merged summary (summary_merged.tsv) is a drop-in replacement for summary.tsv
  in all gen_sample commands.


--- 1.3  gen_sample: filtering, sampling, and export ---

Move into the gen_sample scripts directory:
  cd gen_sample/scripts

Each run writes to a new numbered directory (run_01, run_02, ...) so nothing is
ever overwritten. run_config.json records every parameter for reproducibility.

QUICK START — 20 entries, default stratified sampling:

  python 01_gen_sample.py --sample 20

  Output: gen_sample/outputs/run_01/sample.tsv

DRY RUN — inspect the pool before committing:

  python 01_gen_sample.py --dry-run --max-peptide 15 --min-year 2005

QUALITY FILTERS — narrow the pool before sampling:

  python 01_gen_sample.py --sample 30 \
    --single-chain \
    --max-peptide 15 \
    --min-year 2005 \
    --max-resolution 2.5 \
    --binding-type kd

REDUNDANCY FILTERS — remove sequence- or structure-redundant entries:

  python 01_gen_sample.py --sample 30 \
    --seq-id-receptor medium \
    --seq-id-peptide strict \
    --tm-score-receptor 0.5

SAMPLING METHODS — five algorithms available:

  # Stratified (default): uniform coverage in a 6x6 quantile grid
  python 01_gen_sample.py --sample 20 --sampling stratified --dims dg pep_len

  # Kennard-Stone: maximizes minimum pairwise distance in feature space
  python 01_gen_sample.py --sample 20 --sampling kennard-stone --dims dg pep_len rec_len

  # KDE: inverse density — over-represents tails of the affinity distribution
  python 01_gen_sample.py --sample 20 --sampling kde --dims dg

  # Cluster: one representative per k-means centroid
  python 01_gen_sample.py --sample 20 --sampling cluster --seed 42

  # Isolation-forest: favors outliers in N-D feature space
  python 01_gen_sample.py --sample 20 --sampling isolation-forest

  # Sample by functional class + affinity
  python 01_gen_sample.py --sample 20 --sampling kennard-stone --dims func_class dg

EXPORT — get structure files and sequences:

  # Symlinks (fast, saves disk space)
  python 01_gen_sample.py --sample 20 --link-cifs

  # Copies in PDB format, protonated at pH 7.4
  python 01_gen_sample.py --sample 20 --copy-cifs --format pdb --protonate --ph 7.4

  # FASTA sequences for alignment
  python 01_gen_sample.py --sample 20 --export-fasta

MERGED DATASET — include external sources:

  python 01_gen_sample.py --sample 30 \
    --summary-tsv ../../scrape_pdb_bind/outputs/summary_merged.tsv \
    --full-metadata

COMPARE SAMPLING METHODS on the same pool:

  python 02_benchmark_sampling.py --n 20 --seed 42 --dims dg pep_len

  Output: gen_sample/outputs/plots/sampling_benchmark.png

VISUALIZE A RUN's distribution:

  python 03_compare_runs.py --run run_01

  Output: gen_sample/outputs/run_01/plots/run_comparison.png


--- 1.4  Visualizing a sample in PyMOL ---

Browse the fixed structures of a sample run (arrow keys to navigate):

  # First generate a sample with CIF copies
  python 01_gen_sample.py --sample 20 --copy-cifs

  # Then view it
  python 05_view_sample.py --run 1

  # Or point to an existing cif/ directory
  python 05_view_sample.py --run 2 --cif-dir cif

  Structures are displayed in ΔG order (tightest binder first).
  The status line shows: pdb_id, dG, peptide chain:length, receptor chain:length.

PART 2 — APPLICATION WORKFLOWS

--- A.  MD simulation input preparation (CHARMM-GUI / GROMACS) ---

Goal: obtain a single protonated PDB file for a specific complex, ready to
      upload to CHARMM-GUI Solution Builder or use directly with GROMACS.

The --pick mode bypasses all filters and returns the fixed, optionally
protonated structure for any PDB ID in the dataset.

  cd gen_sample/scripts

  python 01_gen_sample.py \
    --pick 2las \
    --format pdb \
    --protonate \
    --ph 7.4

  Output: gen_sample/outputs/run_XX/pdb/2las.pdb

The PDB file has:
  - Missing residues filled by PDBFixer (modeled loops, capped termini).
  - Non-standard residues replaced with AMBER14 equivalents.
  - Missing hydrogens added at the specified pH.
  - Peptide and receptor as separate chains — no covalent continuity issues.

From here:
  CHARMM-GUI:  Upload 2las.pdb → Solution Builder → set box, ions, water model.
  GROMACS:     gmx pdb2gmx -f 2las.pdb -ff amber14sb -water tip3p

To prepare a small set of related complexes (same receptor, different peptides):

  python 01_gen_sample.py \
    --no-sample \
    --max-receptor 200 \
    --seq-id-receptor strict \
    --format pdb \
    --protonate \
    --ph 7.4

  All accepted structures are copied to run_XX/pdb/, one file per complex.


--- B.  Docking benchmark dataset ---

Goal: a diverse, non-redundant set of peptide-protein complexes with known
      binding poses and experimental affinities, for validating docking
      protocols (pose prediction accuracy, enrichment).

Requirements: receptor diversity (different folds), peptide length range,
high-quality crystal structures, known ΔG for ranking validation.

  cd gen_sample/scripts

  python 01_gen_sample.py \
    --sample 50 \
    --single-chain \
    --max-resolution 2.5 \
    --max-peptide 15 \
    --seq-id-receptor strict \
    --tm-score-receptor 0.5 \
    --sampling kennard-stone \
    --dims dg pep_len rec_len \
    --copy-cifs \
    --format pdb \
    --full-metadata \
    --seed 42

  Output:
    run_XX/pdb/          50 receptor-peptide PDB files (peptide removed = receptor only for re-docking)
    run_XX/sample.tsv    Affinity, chain layout, SS class — scoring reference
    run_XX/run_config.json  Reproducibility record

  Suggested workflow:
    1. Strip peptide chain from each PDB → apo receptor for blind docking.
    2. Re-dock with your protocol (AutoDock-GPU, Glide, HADDOCK, etc.).
    3. Evaluate pose RMSD against the co-crystal peptide chain in sample.tsv.
    4. Use dG_kcal_mol for ranking/enrichment metrics.

  The kennard-stone sampler with three dimensions (dG × pep_len × rec_len)
  ensures the benchmark spans the full complexity space, not just the mode.


--- C.  Machine learning ΔG prediction dataset ---

Goal: a clean, non-redundant, split-ready dataset of peptide-protein complexes
      with experimental ΔG for training or benchmarking ML binding affinity
      models (sequence-based, structure-based, or graph neural networks).

  cd gen_sample/scripts

  # Full non-redundant pool (no N limit) with all metadata columns
  python 01_gen_sample.py \
    --no-sample \
    --seq-id-receptor medium \
    --seq-id-peptide medium \
    --max-added 3 \
    --max-receptor-added 5 \
    --full-metadata \
    --export-fasta \
    --summary-tsv ../../scrape_pdb_bind/outputs/summary_merged.tsv

  Output:
    run_XX/sample.tsv              All entries: sequences, SS, dG, resolution, year, func_class
    run_XX/peptide_sequences.fasta  For sequence-based models
    run_XX/receptor_sequences.fasta

  Key columns in sample.tsv for ML features:
    dG_kcal_mol            Target (continuous regression or classification)
    peptide_seq            Peptide amino acid sequence (1-letter)
    receptor_seq           Receptor sequence per chain: "A:MKTAY...|B:ACDEF..."
    peptide_pct_helix/beta/coil   Secondary structure fractions
    receptor_func_class    Receptor category (enzyme, kinase, regulatory, etc.)
    resolution             Structure quality indicator
    year                   Useful for temporal train/test splits

  Suggested train/test split:
    Temporal:   year <= 2018 → train,  year > 2018 → test
    Sequence:   use receptor_seq with CD-HIT at 30% to define splits
    Random:     shuffle sample.tsv, 80/10/10 split by row

  For graph neural network inputs (e.g. EquiBind, DiffDock):
    Use --link-cifs or --copy-cifs to get structure files alongside sample.tsv.


--- D.  AlphaFold-Multimer benchmark ---

Goal: a set of experimental peptide-protein complexes to evaluate how well
      AlphaFold-Multimer (or similar co-folding models) predicts peptide
      binding mode and interface geometry.

Selection criteria: single-chain receptor, peptide <= 20 aa,
high-resolution crystal structure, sequence-diverse receptors.

  cd gen_sample/scripts

  python 01_gen_sample.py \
    --sample 40 \
    --single-chain \
    --max-peptide 20 \
    --max-resolution 2.0 \
    --seq-id-receptor strict \
    --seq-id-peptide medium \
    --sampling kennard-stone \
    --dims dg pep_len \
    --export-fasta \
    --copy-cifs \
    --full-metadata \
    --seed 42

  Output:
    run_XX/peptide_sequences.fasta    Input sequences for AF-Multimer
    run_XX/receptor_sequences.fasta
    run_XX/pdb/ or cif/               Reference experimental structures
    run_XX/sample.tsv                 Metadata for result analysis

  Evaluation workflow:
    1. Run AF-Multimer on each (receptor_seq, peptide_seq) pair.
    2. Align predicted complex to the experimental CIF/PDB.
    3. Compute interface RMSD (peptide Ca RMSD after receptor superposition).
    4. Correlate prediction confidence (pTM, ipTM) with actual interface RMSD.

  The strict receptor redundancy filter (30% seq-id) ensures the benchmark
  covers diverse folds, not just well-sampled receptor families.


--- E.  Peptide design / lead optimization ---

Goal: retrieve all known binders for a specific receptor target from the
      dataset as structural and sequence templates for peptide design or
      in silico optimization.

Scenario: you are designing a peptide inhibitor for MDM2 (p53-binding domain).
Several MDM2-peptide crystal structures are in PDBbind.

  cd gen_sample/scripts

  # 1. Identify the PDB IDs of interest with a dry-run
  python 01_gen_sample.py \
    --dry-run \
    --summary-tsv ../../scrape_pdb_bind/outputs/summary_merged.tsv

  # 2. Extract a specific known MDM2-peptide complex
  python 01_gen_sample.py \
    --pick 1ycr \
    --format pdb \
    --protonate \
    --ph 7.0

  # 3. Get all MDM2-related entries (filter by receptor length range known for MDM2)
  #    and export with full metadata for sequence analysis
  python 01_gen_sample.py \
    --no-sample \
    --min-receptor 90 \
    --max-receptor 130 \
    --max-peptide 20 \
    --full-metadata \
    --export-fasta \
    --copy-cifs \
    --format pdb

  Output:
    run_XX/receptor_sequences.fasta   Receptor variants (point mutations, constructs)
    run_XX/peptide_sequences.fasta    Known binder sequences — use as starting templates
    run_XX/pdb/                       Co-crystal structures for visual inspection
    run_XX/sample.tsv                 ΔG values — rank known binders by affinity

  The peptide_sequences.fasta can be fed into:
    - MUSCLE / Clustal Omega for MSA of known binders
    - ProteinMPNN or RFdiffusion for sequence design guided by the binding interface
    - AlphaFold-Multimer to validate designed sequences before synthesis

  The dG_kcal_mol column in sample.tsv provides the experimental affinity ladder
  to calibrate your design: what ΔG range are you trying to improve on?


--- F.  Virtual screening validation set ---

Goal: a balanced set of known binders (positives) and weak/non-binders
      (negatives) for computing ROC curves and validating a virtual screening
      or scoring function.

Strategy: use ΔG thresholds to define strong binders (positives) and weak
binders (negatives), ensuring structural diversity in both classes.

  cd gen_sample/scripts

  # Strong binders — positives (dG <= -9 kcal/mol)
  python 01_gen_sample.py \
    --sample 30 \
    --max-dg -9.0 \
    --single-chain \
    --seq-id-receptor medium \
    --sampling kennard-stone \
    --dims dg pep_len \
    --copy-cifs \
    --full-metadata \
    --seed 42

  # Weak binders — negatives (dG >= -6 kcal/mol)
  python 01_gen_sample.py \
    --sample 30 \
    --min-dg -6.0 \
    --single-chain \
    --seq-id-receptor medium \
    --sampling kennard-stone \
    --dims dg pep_len \
    --copy-cifs \
    --full-metadata \
    --seed 42

  Combine both sample.tsv files and label:
    dG <= -9.0  → active = 1
    dG >= -6.0  → active = 0

  Evaluation workflow:
    1. Run your scoring function (Vina, MM-GBSA, ML model) on all complexes.
    2. Rank by predicted score.
    3. Compute ROC-AUC and enrichment factor (EF1%, EF5%) against the labels.

  Notes:
    - Both sets use the same redundancy threshold so receptor overlap is minimal.
    - --full-metadata exports all structural features (SS, resolution, year) for
      post-hoc analysis of which complex properties drive model errors.
    - The ΔG gap (-9 to -6) avoids ambiguous mid-affinity cases in the label.


=============================================================================
TIPS
=============================================================================

Reproducing a run exactly:
  run_config.json records every flag used. To reproduce:
    cat gen_sample/outputs/run_01/run_config.json

Checking what's in the pool before committing:
  Always use --dry-run first when exploring a new filter combination.
  It prints pool size at each filtering stage without writing any output.

Working with multiple external datasets:
  python 05_external.py --input ... --name source_a
  python 05_external.py --input ... --name source_b
  python 05_external.py --merge-only
  # summary_merged.tsv now contains PDBbind + source_a + source_b

Disk usage:
  --link-cifs uses symlinks (negligible disk). Use --copy-cifs only when
  you need portable, self-contained run directories.

Updating after a new PDBbind release:
  Re-run 01_download.py and 02_filter.py. The cache mechanism in step 2
  skips previously processed entries and only processes new ones.
